# ДИАГНОСТИЧЕСКИЙ ОТЧЁТ: CMP 90HX после EFI-бута v3.02-full (Code 43)

**Дата:** 2026-08-25 | **Хост:** Windows-система, primary = Intel HD 4600 (iGPU)
**Карта:** PCI\VEN_10DE&DEV_220D&SUBSYS_155510DE&REV_A1 (CMP 90HX, GA102, sm_86)
**BAR0:** 0xF2000000–0xF2FFFFFF (16 МБ)
**Драйвер:** oem1.inf = `nvaci.inf` 32.0.15.8194 (**581.94**, 18.11.2025), путь DriverStore
`nvaci.inf_amd64_ac628b655126e8a1`; устройство переименовано INF-ом в
«NVIDIA GeForce RTX 3070 Ti», VideoProcessor честно = «NVIDIA CMP 90HX».
Установлен 24.08.2026 22:22 (переустановка 23:39).

## 1. Контекст

Загрузка выполнялась с EFI-флешки **cmp90-unlock-v3.02-full**
(unlock_v3f.efi v3.02 FULL: compute+render+gen2) → далее Windows.
Карта оказалась в нерабочем состоянии («странное состояние»). Диагностика
проводилась из Windows без перезагрузки.

## 3. Разбор WATCHDOG-дампа

- BugCheckCode **0x1B0**, Param1=0x2, **Param2=0xC000009A
  (STATUS_INSUFFICIENT_RESOURCES)**, Param4=0xFFFFF80334B4EF10 → live-dump
  dxgkrnl-watchdog в момент инициализации видеодрайвера.
- Т.е. старт nvlddmkm упёрся в таймаут/ресурсную ошибку при подъёме GSP-RM и
  был прерван → Code 43. Новых дампов при последующих реинициализациях нет.

## 4. Выполненное восстановление

1. `pnputil /disable-device` + `/enable-device` (цикл ×2, выдержка 30–45 с):
   - Code 43 **снят**: Status OK, CM_PROB_NONE, nvlddmkm RUNNING (~90 МБ в ядре).
   - Win32_VideoController: OK, ConfigManagerErrorCode 0, VideoProcessor = CMP 90HX.
   - НО: `nvidia-smi` → «Failed to initialize NVML: Not Found»;
     прямой CUDA-проб (P/Invoke nvcuda.dll): **cuInit rc=100
     (CUDA_ERROR_NO_DEVICE)**.
2. Вывод: WDDM-оболочка драйвера поднялась, но **RM/GSP-RM не стартовал** —
   управление картой (NVML/CUDA/compute) отсутствует. Дисплейные выходы карты
   не используются (primary = iGPU), визуальных артефактов нет.

## 5. Почему запись в регистры не может восстановить карту / дать полный анлок

1. **Инструмента нет.** В проекте нет Windows-хелпера доступа к MMIO
   (rm_reg.c/bar0.c — только Linux; inpout/WinIo/RWEverything отсутствуют).
   Из пользовательского режима BAR0 недоступен. Развёртывание тестового
   signed-драйвера потребует testsigning+ребут — отдельной задачи.
2. **И главное — это не поможет:**
   - PLM (0x823804) после POST и так открыт (0xFFFFFFFF, доказано зондом v1);
     его запись не влияет на способность GSP-RM загрузиться.
   - SS0 (0x82381c) / SS1 (0x823820) с хоста **аппаратно игнорируются**
     (подтверждено ранее на v9b/v9c-патчах). Полный анлок требует исполнения
     V67-payload **изнутри GSP-RM** (EFI-этап до загрузки ОС).
   - Текущий отказ — заклинившее состояние GSP/FW после EFI-прогона,
     хостовыми записями не лечится.

## 6. Оценка причины

Сегодняшний EFI v3.02-full оставил GPU в промежуточном состоянии (crafted
booter/FLR-минициклы не завершены штатно либо завершены не полностью), после
чего GSP-RM драйвера 581.94 при старте получил таймаут → TDR live-dump → 43.
Косвенные факторы: служба EventLog сегодня вообще не поднялась (аномалия бута);
поведение v3.02-full на этой системе ранее не документировано (основной
тестовый стенд проекта — другой хост; F:\llama здесь отсутствует).

## 7. Рекомендации

1. **Полное обесточивание** (выключить БП/выдернуть шнур на ~30 c) → карта
   пройдёт собственный чистый POST → ожидаемо вернётся рабочий сток
   (как было до 24.08 23:40).
2. Полный анлок — только корректным прогоном EFI: дождаться баннера версии и
   маркера завершения «Конец.» ДО передачи управления Windows. При зависании
   FULL — фолбэк `cmp90-unlock-v3.01.img` (compute-only).
3. Зафиксировать (фото) вывод EFI-диагностики этого бута: дошёл ли v3.02-full
   до «Конец.», какие значения PLM/SS0/SS1 печатал — это ключ к разбору.
4. После следующей загрузки проверить службу EventLog (сегодня не стартовала);
   если повторится — отдельная проблема платформы.
5. Для будущих диагностик из Windows полезен хелпер чтения BAR0 (порт rm_reg
   на тестовом KMDF-драйвере) — задача небольшая, решает вопрос мониторинга
   PLM/SS0/SS1/GFW_BOOT_OK (0x118234) без Linux.

## D. Почему Superposition ~4 FPS — это норма для CMP 90HX

Graphics (PGRAPH) на CMP 90HX отключён **прошивкой GSP-RM** (whitelist device-ID
@ firmware 0xe037b0 не содержит 0x220D; FEAT_READOUT_0 bit8=0 — следствие).
PGRAPH-регистры power-gated (0xBADFxxxx), инициализация пропускается.
Compute-анлок (PLM/SS0/SS1) на растеризацию не влияет. Дополнительно Superposition
по умолчанию рендерит на primary-адаптере (Intel HD 4600), у которого на
тяжёлых пресетах как раз единицы FPS. Полноценный graphics-unlock пока
НЕ найден (см. cmp90hx-unlock-latest/research/GRAPHICS_UNLOCK_ANALYSIS.md:
зонд 0x823808, PMC_ENABLE bit12, спуфинг device-ID — направления не закрыты).
